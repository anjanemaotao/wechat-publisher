# 微信群二维码图片抓取

自动完成：置前微信 → 搜索指定群 → 进入群聊 → 打开群二维码 → 截图保存。

**只出图片，不解码二维码**（不需要群链接文本）。

## 环境要求

| 依赖       | 版本   | 说明                              |
| ---------- | ------ | --------------------------------- |
| Windows    | 10/11  | 仅支持 Windows                    |
| Node.js    | ≥ 18   | 下载：https://nodejs.org/         |
| AutoHotkey | **v2** | 下载：https://www.autohotkey.com/ |

⚠️ AutoHotkey **必须装 v2**，v1 跑不了。

首次使用先装依赖（在 `scripts` 目录下执行）：

```bash
cd scripts
npm install
```

## 使用

```bash
node scripts/step-click-group.js
```

**不接受任何命令行参数。** 所有配置一律读 `config.json`，要改群名、坐标、截图范围、等待时间，都直接编辑这个文件。

结束会打印绝对路径和机器可读格式，方便上层程序抓取：

```
OUTPUT_PATH=C:\...\wechat-qrcode\output\qrcode.png
```

退出码：`0` 成功，`2` 配置检查未通过，`1` 执行失败。

⚠️ **执行期间不要操作鼠标键盘**，脚本会真的动鼠标点微信。

## 它做了什么

固定五步点击，全程约 10 秒：

| 步  | 动作                               | 坐标                |
| --- | ---------------------------------- | ------------------- |
| 1   | 关残留弹窗 + 最大化置前微信        | **只做这一次**      |
| 2   | 点搜索框，粘贴群名，等搜索结果     | 搜索框              |
| 3   | 点搜索结果里的群聊行 → 进群        | `目标群行.点击坐标` |
| 4   | 点右上角「…」→ 群资料面板          | `聊天信息.点击坐标` |
| 5   | 点「群二维码」→ **截这唯一一次图** | `群二维码.点击坐标` |

**全程只截一张图**，就是最后的二维码弹窗，前四步不截 —— 它们只是中间状态，截了既慢又没用（曾用 `--取证` 全截一遍，白花 4~5 秒）。

## 产物

| 文件（相对 `output/`） | 内容                                  |
| ---------------------- | ------------------------------------- |
| `qrcode.png`           | **最终结果** — 群名 + 二维码 + 有效期 |

输出目录固定为 skill 下的 `output/`，文件名由 `config.json` 的 `二维码截图.输出文件名` 决定。

## 配置项详解

全部配置在 `config.json`，每个字段都带 `_说明` 注释。**这是唯一的配置来源**，脚本不读命令行参数。

### 坐标类

| 字段                | 含义                                         |
| ------------------- | -------------------------------------------- |
| `搜索.点击坐标`     | 微信左上角**搜索框**                         |
| `目标群行.点击坐标` | 搜索下拉里目标群那一行 ★唯一需要按群调整的值 |
| `聊天信息.点击坐标` | 聊天窗口右上角的**「…」**                    |
| `群二维码.点击坐标` | 群资料面板里的**「群二维码」**入口           |

⚠️ **只在换电脑 / 换分辨率 / 换微信版本时才需要改**。

## 换群后必做：重测群聊行坐标

搜索下拉里目标群落在哪个分区取决于该群访问频率，**坐标会差 60+ px**：

| 分区                                   | 实测坐标              |
| -------------------------------------- | --------------------- |
| **最常使用**（紧贴搜索框，第一个分区） | **(177, 135)** ← 默认 |
| 群聊（上面压着「搜索网络结果」分区）   | 约 (205, 202)         |

重测方法（手工，一次性）：

1. 微信里搜目标群名，看下拉列表里它落在哪个分区
2. 把鼠标移到那一行的**群名文字**上，用屏幕坐标工具读出 (x, y)
3. 填进 `config.json` 的 `目标群行.点击坐标`

坐标读数工具：AutoHotkey 自带 `Window Spy`，或`Snipaste`等截图工具取坐标。

## 常见问题

**Q：AHK 弹出警告框卡住**
现象二选一，都是「脚本没反应、stderr 空、看不出原因」：
1. 弹窗 `Script file not found. D:/.../ErrorStdOut` —— 传了 `/ErrorStdOut`，`/` 被当路径分隔符
2. 弹窗 `Script file not found. --ErrorStdOut` —— 改双横线，AHK v2 不认，当成脚本名

**两种写法都错，已全部弃用。** 现在 `spawn(AHK_EXE, [DRIVER])` 不传任何开关，
语法错改为靠「5 秒内 `up.txt` 无 `UP`」快速失败暴露（见下）。

⚠️ **`wechat-driver.ahk` 里的 `_drv` 目录必须用 `A_ScriptDir` 推导，绝不能硬编码。**
曾硬编码 `...\skills\wechat-qrcode\scripts\_drv`，而 skill 目录已改名成
`wechat-qrcode-yashu`，AHK 把 `up.txt` 写进没人读的旧目录，Node 侧永远等不到 —— 同样表现为
「卡住 + stderr 全空」。这是本skill 最难查的一个坑，`A_ScriptDir` 随文件走，改名搬家都不会再错。

排查时用 `AutoHotkey64.exe wechat-driver.ahk` 手工启动，4 秒后看
`scripts/_drv/up.txt` 是否出现 `UP`；不要加任何 `/xxx` 开关。

⚠️ AHK v2 常见坑见下方「实现要点」。

**Q：找不到 AutoHotkey v2**
把 exe 路径写进环境变量 `AHK_PATH`。

## 实现要点（维护者看）

**为什么截图放在 Node 而不是 AHK**：微信是 Qt 渲染窗口，走 DWM 合成层。
AHK 用 `PrintWindow`/`BitBlt` 抓只能得到**全黑**，nut-js 走 GDI 屏幕 DC 才能拿到真实像素。

**为什么只截区域不截全屏**：截全屏要抓 2560x1440（3.7M 像素），再解码、裁剪、重新编码，实测吃 1.4 秒。
`screen.captureRegion` 直接按区域抓，268x346 只要 150ms。

⚠️ nut-js 的坑：`fileName` 传绝对路径会被当成相对路径拼到 cwd 上，
所以代码里传相对文件名，再用 `path.join` 拼绝对路径。

**为什么 AHK 走文件而不是管道**：本机实测 `FileReadLine("*")` 阻塞无响应，
`FileAppend(..., "*")` 即使 `Start-Process -RedirectStandardOutput` 也收不到。写普通文件正常。
指令往返 120~350ms，相比原先每次起进程（3~8 秒）**提速 25~80 倍**。

**失败即停**：任何一步异常立刻退出，不重试、不兜底、不重复置前。现场保持原样便于排查。
主流程抛异常时用 `killNow()` 硬杀 AHK 进程，避免残留。

### AHK v2 踩坑清单

| v1 写法             | v2 正确写法                       |
| ------------------- | --------------------------------- |
| `StrTrim(x)`        | `Trim(x)`                         |
| `StrJoin(arr, ",")` | **无此函数**，用 `.=` 循环拼      |
| `e.WhatLine`        | `e.Line`                          |
| `StrSplit(s, d, 2)` | 第三参是 **maxParts**，误用会越界 |

- **加载期警告弹框，`try/catch` 捕获不到** —— 语法错误发生在代码执行前，会弹 GUI 框把进程卡死，Node 侧只能等超时。必须靠 `/ErrorStdOut` 排查。
- **`for i in arr` 给的是值不是索引** —— 要索引得写 `for idx, val in arr`。
- **`;` 是语句分隔符** —— `x := 1; 注释`（无空格）后半句会被当代码解析。注释前留空格。
- **`CallbackCreate` 第 3 参起要求 ByRef 变量** —— 直接传字符串字面量会报 `requires a Number, but received a String`。
- **切勿在注释里写会触发解析的代码片段** —— 会让报错行号指向上面几行，误导排查方向。
